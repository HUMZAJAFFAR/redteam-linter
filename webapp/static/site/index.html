Why it exists

Most Python linters check style. Most SAST tools are heavy, noisy or SaaS.

This is a small tool you can read end to end in an afternoon, built for the audit workflow: point it at a target, get the risky call sites ranked, triage them, export something safe to attach to a writeup.

The problem with grep

Pattern matching flags docstrings, comments and dead code. It cannot tell subprocess.call(argv) from subprocess.call(cmd, shell=True), and it has no idea whether the argument came from a request.

What this does instead

The analyzer walks the real parse tree, resolves import aliases, checks every call against a YAML rule table and escalates the ones whose arguments trace back to user input. Secrets are harvested in the same pass.

Capabilities

Detection, triage and a redaction boundary that holds.

Sink detection

eval, exec, compile, os.system, os.popen, subprocess.call and pickle.loads, with alias resolution and shell awareness.

Credentials

AWS key IDs, GitHub and Slack tokens, PEM private keys, JWTs, bearer tokens and generic assignments — with placeholder filtering to keep the noise down.

Triage workflow

Mark findings open, confirmed, false positive or fixed; filter by severity and status; group by file or by severity; open any finding for its masked source line.

Assistant

Ask about any finding. It sees only redacted fields, answers offline from a remediation catalogue, and upgrades to a model only if you configure a key server-side.

Server-side redaction

Redaction happens once, in the reporter: evidence keeps four characters, source excerpts mask the value and keep the line, and the browser never receives the raw bytes.

Deterministic output

The terminal report and the JSON export come from the same generator, so a finding looks identical in your shell, in the console and in the file you attach to a ticket.

How it works

Three steps, no build pipeline.

1

Add a target

Paste code or drop up to 25 Python files. Nothing is written to disk and no state survives the request.

2

Scan

Every call is checked against sinks.yaml; credentials are harvested in the same AST pass, and findings are ranked by severity.

3

Triage and export

Mark status, group the results, open the source excerpt, then download the redacted JSON report.

Rule set

Seven sinks out of the box, one YAML file to extend.

Rules are declared, not hard-coded. Add a callable, a category and an optional shell requirement — aliases are resolved for you.

execRCEArbitrary statement execution

os.systemRCEAlways runs through the system shell
os.popenRCEPipes a shell command
subprocess.callRCEFlagged only with shell=True
pickle.loadsDESERCode execution during deserialization

Security posture

A tool that finds secrets should not leak them.

The console is loopback-only by design. Everything below is implemented, not aspirational — see the security page for the full threat model.

Hardened HTTP surface

Strict CSP with no inline script or style, nosniff, no referrer, COOP/CORP, a cross-origin write guard, a 2.5 MB body cap and per-route rate limits.

Two-pass redaction

The engine masks values it recognised; the reporter scrubs every text field again before serialization. The assistant sees eight whitelisted fields and no source bytes.
