Changelog

Release history.

Versions are semantic. The engine, the reporter and the console move together, because the redaction boundary is shared.

0.2.0

2026-11-11 current
  • Console rebuilt. Four views (Scan, Findings, Rules, Assistant) behind a hash router, with severity and triage filters, sorting and file/severity grouping.
  • Triage workflow. Findings can be marked open, confirmed, false positive or fixed; status persists in the browser and survives reloads.
  • Masked source viewer. Every finding carries a redacted excerpt with the flagged line highlighted and credential values replaced, never the raw line.
  • Assistant. Answers offline from a remediation catalogue; optional OpenAI-compatible model mode with a server-side key and an eight-field whitelist.
  • Notification centre. Scans, triage changes, exports, assistant replies and failures are recorded with an unread badge.
  • Hardened HTTP surface. Strict CSP, nosniff, COOP/CORP, origin guard, streaming body cap, per-route rate limits and no-store API responses.
  • Marketing site. Public landing, documentation, security model, changelog and about pages; the console now lives at /app.
  • Web essentials. SVG favicon, manifest, Open Graph meta, robots.txt, print styles, skip link and cursor-following tooltips.

0.1.0

2026-11-10
  • Engine. AST sink matching with import-alias resolution, shell=True awareness and a taint heuristic over request/argv/input sources.
  • Secret harvesting. AWS, GitHub, Slack, PEM, JWT, bearer and generic credential patterns with placeholder filtering.
  • Reporter. Single redaction enforcement point, Rich terminal table and deterministic JSON export.
  • Rules. Declarative sinks.yaml with validation and a built-in fallback table.
  • First console. Paste/upload target, redacted findings table, rule inspector and JSON export.
