About

A small tool you can actually read.

RedTeam Linter started from a simple frustration: most of the Python in an engagement is reviewed by hand, and the tooling either checks style or wants an account on someone else's server. This one is a few thousand lines, no build step, no telemetry, no upload.

Principles

Four rules the code follows.

1 · Never render a raw secret

Not in the terminal, not in JSON, not in the browser. Redaction is output-side and lives in exactly one file, so there is one place to audit.

2 · Keep the evidence structural

Analysis keeps the original bytes, and arguments_passed stays intact, because masking everything would destroy the data future taint tracing needs.

3 · Config over code

New sinks go in sinks.yaml. An invalid file degrades to the built-in table instead of breaking a scan mid-engagement.

4 · Run anywhere Python runs

No bundler, no npm, no CDN. The console is plain HTML, CSS and Java-Script served by the same process as the API.

Limits

What it deliberately does not do.

Honest scope is part of the design. These are known and documented rather than hidden.

  • No interprocedural analysis. Taint is a heuristic over the flagged call's arguments, not a call-graph proof.
  • No project indexing. Files are parsed independently, so cross-file data flow is invisible.
  • No authentication. The console is a loopback tool; it assumes you are the only user.
  • No hosted service. Nothing is uploaded, so nothing is shared between machines — including triage state.
  • No claim of completeness. Pattern-based credential detection misses encoded or generated secrets.

If a rule is too broad for your codebase, narrow it in sinks.yaml rather than ignoring the finding. The Rules view always shows which rule fired.
